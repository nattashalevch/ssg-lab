# Автоматизация сборки и публикации сайта

## 1. Назначение автоматизации

Автоматизация сборки позволяет сократить количество ручных действий при подготовке статического сайта. Вместо последовательного запуска отдельных скриптов можно использовать заранее определённые команды.

В данном проекте автоматизация реализована с помощью Makefile и генератора MkDocs.

## 2. Локальная сборка проекта

Для выполнения сборки используется команда:

```bash
make build
```

Она последовательно выполняет следующие действия:

1. Запускает скрипт построения графика.
2. Формирует сводную таблицу результатов.
3. Запускает генератор MkDocs.
4. Проверяет корректность документации в строгом режиме.

Для предварительного просмотра сайта используется команда:

```bash
mkdocs serve
```

После запуска сайт становится доступен локально по адресу `http://127.0.0.1:8000/`.

## 3. Проверка строгого режима

В проекте используется команда:

```bash
mkdocs build --strict
```

Строгий режим позволяет выявлять предупреждения MkDocs и считать их ошибками сборки. Это помогает обнаруживать проблемы в структуре документации и ссылках до публикации сайта.

Успешная сборка подтверждает, что генератор смог сформировать статические страницы без ошибок и предупреждений, которые нарушают строгий режим.

## 4. Подготовка к использованию GitHub Actions

GitHub Actions — инструмент автоматизации процессов в репозитории GitHub. С его помощью можно организовать автоматическую проверку и публикацию сайта после отправки изменений в удалённый репозиторий.

Предполагаемый процесс автоматизации:

1. Разработчик изменяет файлы проекта.
2. Изменения отправляются в репозиторий GitHub.
3. GitHub Actions запускает рабочий процесс.
4. Устанавливается необходимая версия Python и зависимости проекта.
5. Выполняется генерация графика и таблицы.
6. Выполняется сборка сайта MkDocs.
7. При успешной сборке подготовленный сайт публикуется на GitHub Pages.

## 5. Фиксация зависимостей

Для обеспечения воспроизводимости используется файл `requirements.txt`, содержащий версии установленных Python-пакетов.

Установка зависимостей в новом окружении выполняется командой:

```bash
python -m pip install -r requirements.txt
```

Использование виртуального окружения позволяет изолировать зависимости проекта от системных Python-пакетов.

## 6. Преимущества автоматизации

Применение автоматизированной сборки обеспечивает:

- повторяемость процесса формирования сайта;
- сокращение ручных операций;
- раннее обнаружение ошибок;
- единообразие результатов локальной и удалённой сборки;
- возможность дальнейшего внедрения непрерывной интеграции и публикации.

## 7. Вывод

В лабораторной работе реализована локальная автоматизация генерации графиков, таблиц и сборки статического сайта с помощью Makefile и MkDocs.

Следующим этапом развития проекта является подключение GitHub Actions для автоматического выполнения сборки и публикации сайта при обновлении репозитория.
