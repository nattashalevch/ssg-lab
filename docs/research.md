# Исследование генераторов статических сайтов

## 1. Введение

Генераторы статических сайтов (Static Site Generators, SSG) предназначены для создания веб-сайтов из исходных файлов: Markdown-документов, текстов, программного кода, изображений и других материалов. В отличие от динамических сайтов, статические страницы формируются заранее и могут размещаться на сервере без необходимости выполнять программный код при каждом запросе посетителя.

Статические сайты широко применяются для публикации документации, научных исследований, образовательных материалов, технических отчётов и результатов вычислительных экспериментов.

## 2. Обзор популярных генераторов

### 2.1 MkDocs

MkDocs — генератор статических сайтов, ориентированный на создание документации. Основным форматом исходных материалов является Markdown, а настройки проекта задаются в YAML-файле.

Преимущества:
- простота настройки и использования;
- быстрая сборка сайта;
- поддержка расширений Markdown;
- интеграция с Git и CI/CD;
- наличие тем оформления, включая Material for MkDocs;
- удобная организация документации по разделам.

MkDocs подходит для публикации отчётов, учебных проектов и технической документации.

### 2.2 Sphinx

Sphinx — генератор документации, широко используемый в Python-проектах. Он поддерживает reStructuredText и Markdown с помощью расширения MyST.

Преимущества:
- автоматическое создание документации по программному коду;
- поддержка математических формул;
- возможность использования ссылок и перекрёстных ссылок;
- большое количество расширений;
- возможность создания документации сложных проектов.

Sphinx особенно полезен для проектов, в которых необходимо описывать программные модули, функции и результаты вычислений.

### 2.3 Pelican

Pelican — генератор статических сайтов на Python. Он предназначен для создания блогов, публикаций и сайтов на основе текстовых материалов.

Преимущества:
- поддержка Markdown и reStructuredText;
- расширяемость с помощью плагинов;
- настройка шаблонов;
- поддержка категорий и тегов;
- возможность автоматизации сборки.

Pelican может применяться для публикации исследовательских материалов и тематических статей.

### 2.4 Quarto

Quarto — инструмент для создания научных и аналитических публикаций. Он позволяет объединять текст, программный код, математические формулы, таблицы, графики и результаты вычислений в одном документе.

Преимущества:
- поддержка Python и R;
- работа с Jupyter Notebook;
- выполнение программного кода при подготовке публикации;
- автоматическое формирование графиков и таблиц;
- поддержка библиографических ссылок;
- экспорт в различные форматы.

Quarto подходит для подготовки воспроизводимых научных отчётов и представления результатов исследований.

## 3. Сравнение генераторов

| Критерий | MkDocs | Sphinx | Pelican | Quarto |
|---|---|---|---|---|
| Основной формат | Markdown | RST, Markdown | Markdown, RST | Markdown |
| Простота освоения | Высокая | Средняя | Средняя | Высокая |
| Научные формулы | Да | Да | Через расширения | Да |
| Графики | Статические изображения | Статические изображения, расширения | Статические изображения | Автоматическая генерация |
| Jupyter Notebook | Через плагины | Через расширения | Через плагины | Встроенная поддержка |
| Документация к коду | Через плагины | Отличная поддержка | Ограниченная | Возможна |
| Темы оформления | Большой выбор | Большой выбор | Темы | Настраиваемые темы |
| Основное применение | Документация | Техническая документация | Блоги и сайты | Научные публикации |

## 4. Выбор инструмента для лабораторной работы

Для практической реализации лабораторной работы выбран MkDocs с темой Material for MkDocs.

Выбор обусловлен простотой настройки, поддержкой Markdown, возможностью структурировать материалы исследования по страницам и интеграцией с автоматизированными системами сборки и публикации.

В рамках проекта MkDocs используется для публикации описания эксперимента, таблиц с показателями, графиков, результатов обработки данных и документации реализованного конвейера.

## 5. Вывод

В ходе обзора были рассмотрены четыре генератора статических сайтов: MkDocs, Sphinx, Pelican и Quarto. Все инструменты позволяют создавать статические веб-ресурсы, однако отличаются функциональностью, сложностью настройки и областью применения.

Для документации и учебных проектов удобен MkDocs, для сложной программной документации — Sphinx, для блогов и тематических сайтов — Pelican, для воспроизводимых научных публикаций — Quarto.

Выбор генератора зависит от целей проекта, формата исходных материалов и требований к автоматизации публикации.


## T2. Исследование способов преобразования результатов эксперимента в веб-страницы

### 1. Статические изображения

Первый способ заключается в выполнении эксперимента с помощью Python и сохранении результатов в виде изображений. Для построения графиков могут использоваться библиотеки Matplotlib и Seaborn.

Полученные изображения сохраняются в формате PNG или SVG и подключаются к страницам статического сайта.

Преимущества:
- простота реализации;
- высокая совместимость с генераторами статических сайтов;
- отсутствие необходимости выполнять вычисления в браузере;
- небольшие требования к инфраструктуре публикации.

Недостатки:
- отсутствие интерактивного взаимодействия;
- изменение данных требует повторного построения изображения;
- график не позволяет самостоятельно выбирать отображаемые параметры.

### 2. Публикация Jupyter Notebook

Второй способ — преобразование ноутбуков Jupyter в веб-страницы. Ноутбук содержит программный код, текстовые пояснения, формулы, таблицы и результаты вычислений.

Для преобразования могут применяться:
- nbconvert;
- MyST-NB;
- Quarto.

Преимущества:
- объединение кода, описания эксперимента и результатов;
- возможность демонстрации последовательности вычислений;
- удобство воспроизведения научных экспериментов;
- поддержка графиков и таблиц.

Недостатки:
- увеличение времени сборки;
- необходимость управления вычислительными зависимостями;
- возможное увеличение размера сайта;
- необходимость контроля выполнения ячеек и сохранения результатов.

### 3. Автоматическая генерация Markdown и CSV

Третий способ предполагает отдельную обработку исходных данных Python-скриптами. Результаты вычислений автоматически преобразуются в Markdown-таблицы, CSV-файлы и изображения.

В рамках практической работы реализован именно этот подход.

Исходные данные хранятся в файле `data/measurements.csv`. Скрипты Python выполняют анализ данных, строят график и формируют сводную таблицу. Makefile объединяет операции в единый конвейер, после чего MkDocs собирает статический сайт.

Преимущества:
- разделение исходных данных, вычислений и представления;
- автоматическое обновление результатов;
- удобство проверки и повторного выполнения эксперимента;
- возможность использования в CI/CD;
- простота хранения результатов в системе контроля версий.

Недостатки:
- необходимость самостоятельно поддерживать скрипты;
- необходимость повторного запуска генерации после изменения данных;
- ограниченная интерактивность статических результатов.

### 4. Сравнение подходов

| Критерий | Статические изображения | Jupyter Notebook | Markdown/CSV |
|---|---|---|---|
| Простота | Высокая | Средняя | Высокая |
| Интерактивность | Низкая | Средняя/высокая | Низкая |
| Автоматизация | Средняя | Высокая | Высокая |
| Воспроизводимость | Зависит от скриптов | Высокая при корректной настройке | Высокая при корректной настройке |
| Размер сайта | Обычно небольшой | Может быть большим | Обычно небольшой |
| Требования к CI | Невысокие | Могут быть высокими | Умеренные |

### 5. Кэширование и воспроизводимость

При автоматическом выполнении научных вычислений важно учитывать время обработки данных. Повторное выполнение одинаковых вычислений может увеличивать время сборки.

Для оптимизации применяются:
- кэширование зависимостей Python;
- сохранение промежуточных результатов вычислений;
- использование контрольных сумм исходных файлов;
- повторное выполнение вычислений только при изменении входных данных.

Для воспроизводимости эксперимента необходимо сохранять исходные данные, исходный код, версии библиотек и параметры вычислений.

В практической работе версии зависимостей зафиксированы в `requirements.txt`, а исходные данные, скрипты и результаты хранятся в Git.

### 6. Вывод по исследованию T2

Для рассматриваемого проекта выбран подход автоматической генерации Markdown и графиков из CSV с помощью Python.

Он обеспечивает разделение данных, вычислений и представления, позволяет повторно выполнять обработку и интегрируется с GitHub Actions.

Преимуществом выбранного решения является простота и прозрачность конвейера. При этом для более сложных научных проектов может быть целесообразно использовать Jupyter Notebook или специализированные инструменты публикации вычислительных исследований.
